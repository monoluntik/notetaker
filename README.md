# Notetaker

Личные заметки, привязанные к дате и времени: теги, календарь (месяц / неделя / день,
перетаскивание), повторяющиеся заметки с изменением отдельных вхождений, напоминания (email +
уведомления во всех открытых вкладках), поиск и фильтры, экран «Предстоящие», корзина,
настройки почты и часового пояса. Решение задания 1 «Notetaker» из «Задания Agentic Developer».

- Репозиторий: https://github.com/monoluntik/notetaker
- Материалы сдачи (таблица соответствия заданию, модель и инструмент, промпты, ход работы):
  [`docs/SUBMISSION.md`](docs/SUBMISSION.md)
- Сделано с ИИ-агентом: Claude Code (CLI) + модель Claude Opus 5.5 — промпты дословно в
  [`docs/PROMPTS.md`](docs/PROMPTS.md), хронология в [`docs/WORKLOG.md`](docs/WORKLOG.md).

## Стек
Backend — Python 3.12, FastAPI, SQLAlchemy 2, Alembic, WebSocket. Frontend — React 19 +
TypeScript (Vite), TanStack Query, luxon. БД — PostgreSQL 16. Почта — SMTP в Mailpit
(эмулятор). Тесты — pytest (на реальном PostgreSQL), vitest, Playwright.

## Быстрый запуск (Docker)
**Нужно:** Docker Engine и Docker Compose v2 (проверено на Docker 29.6, Compose 2.39),
свободные порты 8080 и 8025.

```bash
git clone https://github.com/monoluntik/notetaker.git && cd notetaker
docker compose up --build -d          # сборка и запуск в фоне; миграции применяются сами
docker compose ps                     # db, mailpit — healthy; backend, frontend — Up
curl http://localhost:8080/api/health # {"status":"ok","database":"ok"}
```
- Приложение: http://localhost:8080 (откройте во второй вкладке или другом браузере, чтобы
  увидеть синхронизацию).
- Письма-напоминания: http://localhost:8025 (Mailpit). Укажите email в «Настройках», создайте
  заметку через ~11 минут с напоминанием «за 10 минут» — письмо придёт примерно через минуту.

Пароль БД по умолчанию — `notetaker`; другой можно задать в `.env` (пример — `.env.example`).

**Остановка:**
```bash
docker compose stop        # остановить, данные сохраняются
docker compose down        # удалить контейнеры, данные (том notetaker_pgdata) сохраняются
docker compose down -v     # ВНИМАНИЕ: удалит и том с данными
```
**Обновление** после `git pull`: `docker compose up --build -d` (новые миграции применяются при
старте backend).

## Локальная разработка без Docker
Нужны Python 3.12, Node.js ≥ 20 (проверено на Node 26) и PostgreSQL 16 — свой (задайте
`NOTETAKER_DATABASE_URL`) или встроенный из pip-пакета `pixeltable-pgserver`:

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt pixeltable-pgserver
scripts/dev-db.sh start                       # PostgreSQL 16 на 127.0.0.1:5433 (БД notetaker, notetaker_test, notetaker_e2e)

cd backend && ../.venv/bin/alembic upgrade head
../.venv/bin/uvicorn app.main:app --port 8001 --reload          # API на :8001 (занимает терминал)

# во втором терминале, из корня репозитория:
cd frontend && npm install && npm run dev    # http://localhost:5173 (проксирует /api и /ws на :8001)
```
Без Docker письма по умолчанию пишутся в лог backend (`NOTETAKER_EMAIL_BACKEND=console`).
Остановка локальной БД: `scripts/dev-db.sh stop`.

## Тесты
Требуют запущенной локальной БД (`scripts/dev-db.sh start`) — основная база в Docker не
используется и не затрагивается. Тесты пересоздают схемы в базах `notetaker_test` и
`notetaker_e2e` на :5433 (другую базу можно задать через `NOTETAKER_TEST_DATABASE_URL` и `E2E_DATABASE_URL`); база
`notetaker` с рабочими данными не затрагивается.

```bash
cd backend && ../.venv/bin/pytest -q             # 138 тестов на реальном PostgreSQL (notetaker_test)
cd backend && ../.venv/bin/alembic check         # модели и миграции совпадают
cd frontend && npm test                          # vitest, 34 теста
cd frontend && npm run build && npx eslint src e2e   # проверка типов, сборка, линтер
cd frontend && npm run e2e                       # Playwright, 18 сценариев (сам поднимает backend :8011 и Vite :5174, БД notetaker_e2e)
.venv/bin/python scripts/restart_check.py        # SIGKILL и перезапуск реального процесса + SMTP-приёмник
```
Для e2e нужен Chromium: `cd frontend && npx playwright install chromium` (или путь к браузеру в
`PW_CHROMIUM`). Фактические результаты прогонов — [`docs/TESTING.md`](docs/TESTING.md).

## Конфигурация
| Переменная | По умолчанию | Назначение |
|---|---|---|
| `NOTETAKER_DATABASE_URL` | `postgresql+psycopg://postgres@127.0.0.1:5433/notetaker` | БД |
| `NOTETAKER_EMAIL_BACKEND` | `console` (в Docker — `smtp`) | `console`, `smtp` или `memory` (тесты) |
| `NOTETAKER_SMTP_HOST` / `_PORT` / `_FROM` | `localhost` / `1025` / `notetaker@localhost` | SMTP |
| `NOTETAKER_SCHEDULER_INTERVAL_SECONDS` | `15` | Период планировщика напоминаний |
| `NOTETAKER_SCHEDULER_ENABLED` | `true` | Включить планировщик |
| `NOTETAKER_TRASH_RETENTION_DAYS` | `30` | Через сколько дней заметки удаляются из корзины навсегда |
| `NOTETAKER_LOG_LEVEL` | `INFO` | Уровень логов приложения (`notetaker.*`) |
| `NOTETAKER_CORS_ORIGINS` | `["http://localhost:5173", …]` | CORS для dev-сервера |

## Что умеет
- **Заметки:** заголовок, текст, дата и время, теги, «активна / неактивна», создание,
  редактирование, удаление в корзину, восстановление; корзина очищается сама через 30 дней.
- **Теги:** создание, переименование, цвет, удаление; у заметки несколько тегов (минимум один).
- **Повторения:** каждый день / неделю / месяц с датой окончания; изменить, перенести или удалить
  одно вхождение; изменить серию «с этого вхождения», не трогая прошлые.
- **Напоминания:** за 10 минут, 1 час, 1 день (несколько сразу); письмо ровно одно на
  напоминание; уведомление в интерфейсе во всех открытых вкладках, после перезагрузки страницы
  показанное не всплывает; неактивные и удалённые не напоминают; активированные или
  восстановленные после срока не досылают прошедшие.
- **Календарь:** месяц, неделя, день; клик открывает заметку; перетаскивание переносит её (у серии
  — только вхождение).
- **Список:** поиск по заголовку и тексту по всей базе, фильтры по тегам, статусу и периоду,
  сортировка по дате заметки и дате изменения, пагинация.
- **«Предстоящие»:** сегодня, эта неделя и отдельно прошедшие активные; заметка переходит в
  прошедшие без перезагрузки.
- **Настройки:** email и часовой пояс (меняет отображение, но не момент напоминания).
- **Несколько клиентов:** изменения в одной вкладке/браузере видны в других без перезагрузки
  (WebSocket); одновременная правка не теряется молча — устаревшее сохранение отклоняется, а
  форма переносит правки пользователя на актуальную версию.
- **После перезапуска сервера** данные и напоминания сохраняются; напоминания, срок которых
  прошёл во время простоя, отправляются, если событие ещё не началось, и пропускаются, если
  уже началось ([`docs/DECISIONS.md`](docs/DECISIONS.md), D7).
- **Интерфейс:** адаптивный (телефон — нижняя навигация и календарь-повестка, планшет — верхняя
  панель, десктоп — боковая), управление с клавиатуры.

## Состояние проекта
Все обязательные пункты задания реализованы и покрыты автоматическими тестами — таблица
соответствия с доказательствами в [`docs/SUBMISSION.md`](docs/SUBMISSION.md). Нагрузка на
10 000 000 заметок измерена — [`docs/LOADTEST.md`](docs/LOADTEST.md).

### Известные ограничения
- Учётных записей нет (по заданию — на усмотрение): одно рабочее пространство на установку.
- Один экземпляр backend: WebSocket-рассылка в памяти процесса. Несколько экземпляров не
  создадут дублей напоминаний, но вкладки другого экземпляра не получат событие сразу.
- «Ровно одно письмо» гарантируется журналом доставок; если процесс упадёт после того, как SMTP
  принял письмо, но до записи статуса, письмо уйдёт повторно (с тем же Message-ID).
- Поиск находит серию целиком, не указывая, какое вхождение совпало.
- У тегов нет версий: при одновременном переименовании побеждает последняя запись.
- Перетаскивание на сенсорных экранах недоступно (HTML5 DnD) — перенос через форму.
- Серия не длиннее 5 лет; ежемесячно на 29–31 число — последний день короткого месяца.
- На 10 млн заметок экраны по всей базе («Предстоящие», календарь без фильтра) отвечают за
  1.0–1.7 с; глубокая страница (смещение 1 млн) — 0.9 с.
- Не проверялось: физические телефоны, экранные дикторы, Firefox/Safari, ручной просмотр
  интерфейса человеком (только эмуляция в Chromium и автотесты).

### Что сделали бы следующим заходом
Многопользовательский режим (`user_id` и индексы по нему — снимает и ограничения глобальных
экранов на больших объёмах); keyset-пагинация; Postgres LISTEN/NOTIFY для нескольких
экземпляров backend; перенос на сенсорных экранах; версии у тегов; проверка в Firefox/Safari и
на устройствах; расследование падения пропускной способности в последнем нагрузочном прогоне
(см. LOADTEST).
