## 2. Матрица требований → реализация → проверка

Обозначения проверки: **U** — unit-тест (pytest/vitest), **A** — API-тест pytest на реальном
PostgreSQL, **E** — e2e (Playwright) или ручной сценарий из `docs/TESTING.md`.

### 4.1 Заметки
| Требование | Реализация | Проверка |
|---|---|---|
| Поля: заголовок, текст, дата/время, теги, статус, created/updated | `notes`: `title`, `body`, `start_at timestamptz`, `timezone`, `is_active`, `created_at`, `updated_at`; `note_tags` | A: создание/чтение возвращает все поля |
| «Один или несколько тегов» | Валидация: `tag_ids` минимум 1 (422 иначе) | A: пустой список → 422 |
| CRUD | `POST/GET/PATCH/DELETE /api/notes` | A |
| Переключение активности | `PATCH /api/notes/{id}` `{is_active}` | A + UI переключатель |
| Корзина / восстановление | Мягкое удаление `deleted_at`; `GET /api/trash`, `POST /api/notes/{id}/restore`, `DELETE /api/notes/{id}/purge` | A: удалённая не видна в списке/календаре/напоминаниях, после restore видна |

### 4.2 Теги
| Требование | Реализация | Проверка |
|---|---|---|
| Создание/переименование/удаление | `/api/tags` CRUD, уникальное имя без учёта регистра | A: дубликат → 409 |
| Цвет | `color` `#RRGGBB`, валидация | A: неверный цвет → 422 |
| Несколько тегов у заметки | M2M `note_tags` | A |
| Удаление тега, используемого заметкой | 409, если тег — единственный у какой-то заметки, включая корзину; иначе отвязать | A |

### 4.3 Повторения
| Требование | Реализация | Проверка |
|---|---|---|
| daily / weekly / monthly | `notes.recurrence_freq`, генерация в `services/recurrence.py` в TZ заметки | U: генерация, DST, 31-е число |
| Дата окончания обязательна | `recurrence_until` (локальная дата, включительно), обязательна при freq ≠ none, ≥ даты начала | A: без until → 422 |
| Изменить одно вхождение | `occurrence_overrides(note_id, original_start, …)` + `PATCH /api/notes/{id}/occurrences/{original_start}` | A: изменилось только одно вхождение |
| Удалить одно вхождение | override с `is_cancelled=true` | A |
| Тесты границ периодов/окончания/изменения вхождения | — | U+A: until включительно, окно запроса на границе, конец месяца, DST |

### 4.4 Напоминания
| Требование | Реализация | Проверка |
|---|---|---|
| 10 мин / 1 ч / 1 день, несколько | `note_reminders(note_id, offset_minutes ∈ {10,60,1440})` | A |
| Только для активной заметки | Планировщик учитывает `is_active` заметки и override | U/A |

## 3. Риски и меры

| Риск | Почему опасно | Мера |
|---|---|---|
| **Повторения: идентичность вхождения** | После правки серии override может «потеряться» | Вхождение идентифицируется `original_start` (UTC момент по исходному правилу). При изменении времени/правила/TZ серии overrides удаляются (UI предупреждает); при изменении только `until` — остаются, лишние игнорируются |
| **Повторения: 29–31 число** | В феврале нет 31-го | Monthly: «прижимаем» к последнему дню месяца, якорь — исходный день (31 янв → 29 фев → 31 мар). Тесты |
| **Повторения: DST** | «Каждый день в 09:00» должен оставаться 09:00 местного | Генерация в локальном времени TZ заметки, затем перевод в UTC. Несуществующее время (переход вперёд) сдвигается вперёд; неоднозначное — первое (fold=0). Тесты на `America/New_York` |
| **Часовые пояса: смена TZ пользователя** | Наивное хранение сдвинет напоминания | UTC в БД, TZ заметки фиксируется при создании/редактировании; тест |
| **Часовые пояса: границы «сегодня/неделя»** | UTC-полночь ≠ локальная | Границы считаются на сервере в TZ пользователя; тест на TZ +14/−12 |
| **Напоминания: дубли** | Два процесса, повторный скан, краш между отправкой и фиксацией | Уникальный ключ события, `ON CONFLICT DO NOTHING`, advisory lock, outbox с блокировкой строки во время отправки. Остаточный риск (краш после SMTP-ответа до COMMIT) документирован; Message-ID детерминирован для дедупликации на стороне почты |
| **Напоминания: простой сервера** | Пропущенные события | Явная политика D7 + водяной знак `scheduler_state.last_scan_at` |
| **Напоминания: правка заметки после отправки** | Повторная отправка/потеря | В ключ входит `fire_at`: если время сдвинули, новое напоминание — новое событие; отправленные не повторяются |
| **Синхронизация вкладок** | N вкладок → N системных уведомлений / рассинхрон данных | WS-события `changed`; системный Notification с `tag=delivery_id` (браузер схлопывает), «прочитано» синхронизируется через сервер |
| **Пагинация + повторения** | Список нельзя развернуть в SQL | Список работает на уровне серий; фильтр периода — по пересечению диапазона серии (ограничение задокументировано) |
| **Docker недоступен в среде разработки** | Нельзя проверить compose | Тесты на реальном PG 16 без Docker; compose проверить, когда появится доступ; честно отметить в TESTING.md |
